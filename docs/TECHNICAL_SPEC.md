# Техническое задание
## Входы и расписание
RSS сохраняет ETag/Last-Modified. HTML использует заданные CSS-селекторы. JSON API использует путь к массиву, соответствие полей, заголовок с именованной переменной секрета, постраничный обход одного origin и сохраняемый offset. Все запросы имеют ограничение времени, объёма и количества. Запрещён выход через произвольные приватные адреса и обход блокировки источника.

Полное разрешение хранения проверяется до загрузки. 401/403/429/CAPTCHA блокируют источник до действия владельца. Расписание сбора сохраняется в cursors/jobs, дайджесты — в hub_recurring_tasks. Интервал в секундах, окно материалов в часах; это внутренний scheduler приложения.

## Архив и обработка
Raw-ответ хранится по SHA-256 в data/archive; таблица содержит ссылку и метаданные без заголовков авторизации. Material хранит очищенный текст, Story объединяет точные и семантические совпадения. Изменённый текст сохраняется новой версией материала. Архив не удаляется при устранении дублей.

Редакционное ядро выполняет классификацию, кластеризацию, перевод, черновик, проверку и адаптацию. OpenCode принимает текст с явным разделением инструкций и недоверенного материала. Модель не получает право изменять адресатов, токены или отправлять посты.

## Согласование и доставка
Каждый target имеет отдельный Variant и историю. Approval фиксирует SHA-256 содержимого, исходную ревизию, настройки, binding и дату. Редактирование, смена конфигурации или канала делает старое согласование недействительным. Вложения проверяются по байтам, типу, размеру и SHA-256.

Доставка независимо по target. Ошибка одного адресата не вызывает повторную отправку успешному. PostgreSQL FOR UPDATE SKIP LOCKED защищает выборку несколькими workers. Отмена и редактирование согласованы с блокировками отправки. После потери ответа или истечения send lease состояние unknown, без автоматического повторения внешнего эффекта.

MAX использует прежний браузерный транспорт либо официальный Bot API при наличии токена. Пикабу создаёт post.json/post.txt/post.html и вложения; владелец публикует вручную, сохраняет permalink и подтверждает именно текущий snapshot. owner_attested не означает live_verified.

## Панель и права
Владелец: настройки/пауза/сверка/подтверждение ручной публикации. Редактор: версии, файлы, согласование, отмена. Наблюдатель: чтение. HttpOnly-сессия и проверка origin защищают cookie-запросы. Сервер по умолчанию слушает только loopback. Внешнее размещение требует TLS и собственных ролей БД.

## Перенос и приёмка
Архив исходников по allowlist исключает .env.local, БД, браузер и модели. Отдельный зашифрованный backup содержит разрешённую историю, raw-архив и файлы. Restore работает только с пустой мигрированной БД и оставляет отправку на паузе. История исходного MAX импортируется отдельной командой read-only, согласования отзываются, отправки архивируются.
