# Работа редакции

Актуальный сценарий 0.11.5: Postiz `/editorial`, автоматический `max_test`.
Права автоматического согласования ограничены поручениями в [AGENTS](../AGENTS.md).

1. Подбор проверяет возраст источника, полное разрешение и всю историю дублей.
   Для нового формата обязательны фото той же статьи, полный credit и license proof.
2. До HTTP MADLAD строит планы title/body. Затем сохраняются полный перевод,
   raw и hashes; числа, ссылки, факты и язык проходят hard gates.
3. Независимый Ministral и LanguageTool проверяют кандидат по закреплённой
   рубрике `hourly-practical-v2`. Qwen вправе предложить до двух адресных правок;
   каждый изменённый текст заново проходит проверки. Старый отказ не стирается.
4. `quality_ready` хранится локально в PostgreSQL. Postiz DRAFT, approval и
   dispatch появляются только при точном назначении будущего слота.
5. Агент фиксирует решение `hourly_article_policy` для точных текста, картинки,
   даты и адресата. Ручной editor checkbox и owner cookie для этого не используются.
6. MAX получает фото, жирный заголовок, обычное тело и атрибуцию. Доставку
   подтверждают verified dispatch, Postiz PUBLISHED и точное сообщение после reload.
   Между доставками выдерживается минимум 3600 секунд; адресат возвращается на паузу.

Общая пауза подготовки и пауза адресата — разные состояния. Уже назначенный
QUEUE Postiz может требовать онлайн-API даже при общей паузе. Unknown не
возвращается в очередь повторной отправкой. Пустой резерв показывается как
инцидент, а не заполняется текстом с ослабленными проверками.

Для generic/human маршрутов сохраняются отдельные правила ручного согласования.
Пикабу — ручной экспорт; Reddit, Telegram/VK и desktop heartbeat не включены.
Работа с legacy Hub описана в [ручном маршруте](MANUAL_PUBLICATION.md) и не
является инструкцией запуска второго worker на действующей VM.
