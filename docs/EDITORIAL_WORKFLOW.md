# Работа редактора
1. Включить конкретный источник и проверить разрешённые хранение/производные материалы. Источники после переноса отключены.
2. Выполнить collect или дождаться расписания. Найденные материалы появятся в архиве, дубли группируются в Story.
3. Включённая локальная LLM под OpenCode готовит Draft. При недоступной модели задача остаётся с кодом ошибки; шаблон не выдаётся за генерацию.
4. В /hub выбрать вариант адресата, отредактировать заголовок/текст, теги Пикабу и вложения. Сохранить новую версию.
5. Снять паузу нужного адресата, выбрать дату в часовом поясе компьютера, согласовать. Контент-план показывает время в Europe/Moscow.
6. MAX: worker отправит frozen snapshot к сроку. Неопределённый результат сверяется по идентификатору операции.
7. Пикабу: worker сформирует экспорт к сроку; скачать пакет, вручную опубликовать прежним аккаунтом, вставить ссылку и подтвердить. Это свидетельство владельца, без независимого доказательства через API.
8. Перед изменением scheduled/unknown сначала отменить или сверить отправку. Смена текста снимает прежнее согласование.
9. Не повторять публикацию со статусом unknown вручную до поиска фактического результата.

С версии 0.4.0 MAX можно вести в Postiz: draft → правки и календарь QUEUE
→ синхронизация → подтверждение авторского текста при отсутствии источников
→ отдельное approval в агенте → браузерная доставка. Подробный порядок и
ограничения: [MAX browser adapter](MAX_BROWSER_ADAPTER.md).
Обычные Postiz-провайдеры требуют отдельной проверки согласования;
для них общий approval_guard_verified остаётся false.
