# MADLAD в автоматическом цикле MAX/Postiz

Версия 0.9.5, 25 октября 2026 года, Europe/Moscow.

Новый автоматический черновик переводит `madlad400-3b-q4k-causal-v2`.
Проверяется исправленный Candle worker и точные SHA весов, tokenizer и config;
прежний дефектный backend не является допустимым переводчиком. Выбор основан на
[сравнении двадцати статей](TRANSLATION_20_ARTICLES.md), а не на гарантии отсутствия
ошибок. Проверки каждого отдельного текста обязательны.

Цепочка: полный разрешённый исходник → MADLAD → прежние hard gates →
независимый Ministral по полному EN/RU → LanguageTool → точный DRAFT →
policy approval версии/адресата/даты → прежний dispatch worker → проверка MAX.
При известном содержательном отказе отдельный Qwen предлагает адресную правку.
Изменённый кандидат проходит новые Ministral и LanguageTool; неизменённый
отклонённый текст не переоценивается. На запись остаются максимум два заранее
зафиксированных PostgreSQL claim. История исходника, отказов, raw и полного
фактического diff не перезаписывается.

Из [статьи о цикле правок](https://habr.com/ru/articles/1098756/) применены
проверяемое принятие кандидата, независимая проверка после изменения, ограничение
числа правок, сохранение предыдущих версий и остановка при неизвестном исходе.
Общий балл или рекомендация редактора не заменяют проверку фактов и не разрешают
публикацию. Калман, усреднение вердиктов и повторные опросы ради положительного
ответа не добавлены. Политики источников, лимиты часа и защита от дублей прежние.

MADLAD работает на узле моделей через постоянный сервис с отдельными Python и
артефактами. На каждый сегмент создаётся только собственный CPU worker;
после ответа он завершается **до** передачи результата вызывающему приложению,
освобождая память для Ministral. Чужие модели не перезапускаются. Health подтверждает
настройку и hashes, но явно не подтверждает inference.

VM обращается к loopback endpoint через SSH с отдельным ограниченным ключом.
На узле моделей ключ разрешает только фиксированную stdio-команду к MADLAD.
Глобальное разрешение SSH forwarding на OpenMediaVault не изменяется.
Сервис и соединение запускаются systemd; desktop heartbeat не используется.
Raw и диагностические данные остаются в закрытых ignored data.

Запись со старым полностью сохранённым отказом `ARTICLE_REPAIR_LATIN_MASK_FORBIDDEN`
можно адресно поместить в карантин только после чистого воспроизведения того же
отказа по exact trace/input/prompt/claim на общей паузе. Исходный failed claim
сохраняется вместе с отдельным одноразовым Audit. Такой текст не становится
passed, не переводится повторно и не публикуется. Таймаут, потерянный claim,
изменённые доказательства и внешнее состояние сохраняют блокировку.

Применение версии в runtime и публикация подтверждаются отдельной записью
CHANGELOG после живой проверки. Наличие кода и модульных тестов само по себе
не подтверждает доставку.

Живая проверка 25 октября 2026 года завершена: статья NOIRLab
[`iotw2602a`](https://noirlab.edu/public/images/iotw2602a/) переведена MADLAD,
прошла независимый Ministral (approved=true, issues=[]) и LanguageTool
(нерешённых замечаний нет), согласована политикой и опубликована в MAX
в 23:52:08 МСК. Postiz подтвердил PUBLISHED; отдельное чтение MAX с
перезагрузкой в 23:54 подтвердило один пост и точные 1640 символов.
Доставка выполнена одной попыткой. Эта статья не потребовала коррекции Qwen;
живой запуск ветки исправлений на ней не заявляется. Проверки этой ветки
и PostgreSQL claim включены в 414 успешных тестов на VM.

Все 59 исторических записей сохранены. После доставки пять адресатов paused;
единственный серверный цикл продолжает работу, desktop heartbeat выключен.
Проверки качества могут пропустить час при отсутствии допустимого кандидата;
повторы неизвестного исхода и догоняющие пачки остаются запрещены.
