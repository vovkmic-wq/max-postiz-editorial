# Критерии приёмки
| Проверка | Ожидаемый результат |
|---|---|
| Fresh PostgreSQL | Alembic head 0005, без SQLite fallback |
| Дубли/редакции | Не теряется материал, точные дубли не создают повторный эффект |
| Источник 429/CAPTCHA | Blocked cursor, нет автоматического обхода |
| Изменение варианта/файла | Старое approval не даёт отправить пост |
| Два workers | Одна зафиксированная попытка для dispatch |
| Отмена во время sending | Отказ отмены/правки, без гонки с worker |
| Частичный успех | Успешный адресат не отправляется второй раз |
| Unknown | Нет слепого повторного POST |
| Пикабу | Экспорт, валидный story URL, owner_attested/verified=false |
| Postiz draft/edit | Правки импортируются; конкурирующая локальная версия блокирует sync |
| Роли/CSRF | Viewer не согласует, origin проверяется |
| Backup/restore | Зашифрованный полный снимок, пустая БД, targets paused |
| Zip/relocation | Нет секретов/БД/cookies, чистая установка проходит smoke |
| Живая LLM | Генерация русского текста и draft через прежний OpenCode/model |
| Живые площадки | Отдельно согласованная тестовая публикация и чтение результата |
| Postiz runtime | Версия/интеграции/permissions/API проверены на конкретном экземпляре |
| MAX browser bridge | Postiz не получает право согласования; QUEUE без approval не отправляется |
| Правка Postiz MAX | Версия/дата/медиа требуют нового approval; sending/unknown блокируют mutation |
| MAX pending/status | Только verified delivery переводится в completed; unknown не повторяется |

Версия 0.4.0: 276 тестов прошли; 22 ключевых теста повторно прошли.
Версия 0.4.1: 64 проверки затронутых контрактов прошли; один согласованный
пост реально опубликован в MAX и сохранился после reload и новой сессии.
Postiz — PUBLISHED, Temporal — COMPLETED, канал после теста paused.
Подробнее: [живая публикация](MAX_TEST_PUBLICATION_REPORT.md).
В живом Postiz проверены подключение MAX, черновик локальной LLM, редактор,
сохранение правки и pending-вызов провайдера к агенту. Живая отправка MAX
не выполнялась. См. [отчёт адаптера](MAX_BROWSER_ADAPTER_REPORT.md).

Состояния имитации, доступа и ручного подтверждения явно отделены от независимой live-проверки доставки. Недоступные внешние зависимости оставляют живую приёмку незавершённой; зелёный pytest не меняет этот статус.
