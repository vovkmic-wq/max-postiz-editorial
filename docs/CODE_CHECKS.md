## Окружение

Поддерживаемая среда разработки: Python 3.12 и отдельная `.venv` в каждом checkout.
На Windows проверена Python 3.12.0. Пакет имеет src-layout; editable-установка
должна указывать именно на этот `src/max_postiz_agent`. Системный Python может
запускать `python scripts/check.py`: обёртка передаст выполнение своей `.venv`.
Активация окружения не обязательна. При отсутствии `.venv` команда завершится
ошибкой с инструкцией, а не установит зависимости сама.

Сначала выполните команды подготовки из README. Полный набор закреплён в четырёх
файлах: `requirements.lock` (приложение), `requirements-dev.lock` (pytest/Ruff/build),
`requirements-browser.lock` (Playwright), `requirements-deployment.lock` (PyYAML
для тестов конфигурации). Установка — из всех четырёх файлов одновременно, затем
`pip install --no-deps --no-build-isolation -e .`. Setuptools/wheel уже закреплены
в dev lock. Версии проверяются командой; хэши всех wheel-файлов эти locks не фиксируют.
Необязательные ONNX/веса из `requirements-images.lock` для тестов не нужны.

Нужны Git и Node.js в PATH, установленный Google Chrome. Браузер запускается
headless через Playwright с channel=chrome, в отдельном контексте. Пользовательские
cookies и профиль MAX не используются. Тесты оболочек требуют Git Bash на Windows
или bash на Linux; отдельные проверки PowerShell и Linux pipes платформенные.
OpenCode/npm runtime из package-lock.json нужен приложению, но не локальной suite.

## Единая команда и результаты

```text
python scripts/check.py
```

Этапы: совпадение интерпретатора/checkout/версий и locks → `pip check` →
`ruff check src tests scripts` → `ruff format --check` для явно заданных файлов →
`node --check` для обоих JS → готовность изолированного Chrome → полный pytest →
`git diff --check`. При сбое независимые этапы продолжаются; после неуспешного
preflight окружения исполнение останавливается, после отказа Chrome pytest
помечается blocked. Пустой или повреждённый JUnit, отсутствие выполненных тестов,
ненулевой код инструмента или таймаут дают ненулевой общий код.

Каждый запуск получает уникальный `data/check-runs/<UTC>-<id>/`. Там находятся
`report.json`, `tests.xml`, логи этапов и отдельный pytest basetemp. Каталог
создаётся заранее, поэтому pytest не требует вручную создавать его родителя.
Параллельные прогоны не удаляют временные файлы друг друга. Отчёты приватные,
игнорируются Git; содержат фактический интерпретатор, статусы, длительности,
количество passed/failed/errors/skipped и причины пропусков. Секретные переменные
и URL БД в JSON не включаются. Полные тестовые логи не публикуйте без проверки.

Команда не читает `.env.local`. В дочернем окружении удаляются DATABASE_URL,
PYTHONPATH и внешние PYTEST_ADDOPTS/PYTEST_PLUGINS; сторонние autoload-плагины
отключены. Значение TEST_DATABASE_URL передаётся только с `--postgres`.
Плагины/фикстуры, явно указанные в самих тестах, продолжают работать.

## PostgreSQL и внешние сервисы

Полный набор большой: первый измеренный прогон 5091 теста на этом Windows-ПК
занял около 47 минут и обнаружил пять падений стендового адаптера. Это измерение
длительности, не успешная приёмка. Для быстрой обратной связи сначала запускайте
отдельный затронутый тест, затем обязательный полный check. Время другого ПК
или Linux может отличаться; параллельный pytest в текущий процесс не вводился.

```text
python scripts/check.py --postgres
```

До запуска задайте TEST_DATABASE_URL в текущем shell через принятый локальный
менеджер секретов. Нужен URL `postgresql+psycopg`, отдельная БД с именем `test_*`
или `*_tests`, без query-параметров. Пользователю БД нужны CREATE/DROP SCHEMA.
Preflight делает SELECT 1, тесты работают в случайных схемах с их удалением.
Нельзя передавать production-БД, даже если её можно переименовать под этот шаблон.
Команда не создаёт БД, роли, кластеры и не меняет права автоматически.

Без флага PostgreSQL намеренно пропускается и это явно записано как ограничение.
С флагом отсутствие TEST_DATABASE_URL, недоступность БД или соответствующие
пропуски тестов дают ошибку. Изменения транзакций, claims, очереди, резервов и
отправителя требуют успешного PostgreSQL-прогона до заявления готовности.

Postiz/Redis/Temporal, MAX, локальные модели и LanguageTool не нужны для suite.
Она использует SQLite, MockTransport и синтетические HTML/данные; некоторые
фикстуры создают локальный медиаклип с ffmpeg из imageio-ffmpeg. Локальная suite
не запускает сервер, не авторизуется в MAX и не проверяет доставку. Живые проверки
выполняются отдельно по `docs/VM_EDITORIAL.md`, с текущими sending/unknown/lease
guards и согласованием конкретного текста/даты/адресата.

## Отдельная проверка и цикл исправления

Создайте `.test-state`, затем выполните из `.venv`:

```text
python -X utf8 -B -m pytest tests/test_check.py -q --basetemp=.test-state/targeted
python -m ruff check src tests scripts
python -m ruff format --check scripts/check.py tests/test_check.py
python -m pip check
```

Изменяйте путь pytest для своего модуля или `file.py::test_name`. Точечный прогон
не заменяет общую команду перед завершением. Для воспроизведения сначала
сохраните фактическую ошибку. Отделите отсутствие зависимостей/браузера/БД от
поведенческого дефекта. Добавьте регрессионный тест, если он проверяет реальный
контракт, затем сделайте небольшую правку и повторите нужный тест и полный check.
Не пересматривайте ожидаемые значения без требования и не отключайте assertions.

## Ревью и готовность

Перед правками смотрите Git, сохраняйте изменения пользователя. После проверки
отдельно прочитайте весь diff: совместимость интерфейсов, обработку ошибок и
таймаутов, cleanup ресурсов, параллельный доступ и безопасность истории.
В отчёте должны быть команды, фактические результаты, пути доказательств и
непроверенные части. Успешный check, обоснованные skips, согласованные версии
pyproject/__init__ и новая запись CHANGELOG — критерии локальной готовности.
Для инфраструктурных изменений также нужна соответствующая изолированная
интеграция; факт публикации подтверждается независимо в MAX.

## Существующий долг и CI

Общий Ruff lint обязателен целиком, без новых исключений ради зелёного результата.
При исходном прогоне было 55 замечаний в семи файлах; они исправлены небольшими
правками. Составные инструкции тестов разнесены без изменения их AST; fixture
imports переведены на pytest_plugins, лишнее имя сделано явным, zip получил strict.

Массовое форматирование существующего дерева — отдельная миграция: исходный
`ruff format --check src tests scripts` предложил изменить 213 файлов. Сейчас
обязательны `scripts/check.py` и `tests/test_check.py`, область задана в
`tool.max-postiz.check.format-paths`. Mypy/pyright и полный formatter gate ранее
не были настроены и в текущую задачу не вводятся. Никакое покрытие типов не заявляется.
Закреплённый Starlette сообщает deprecation httpx TestClient; смена HTTP-стека
требует отдельной совместной проверки и не выполняется ради удаления warning.

В репозитории нет существующих CI workflows; скрытый или удалённый CI не заявляется
проверенным. При добавлении CI используйте подготовку этой же `.venv` и ту же
команду; для серверной приёмки предоставьте изолированный PostgreSQL и `--postgres`.
