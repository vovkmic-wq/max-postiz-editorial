# Редакция MAX / Пикабу / Postiz

Связка Python + PostgreSQL + OpenCode для сбора материалов, архива,
дедупликации, перевода, редактирования и согласованной публикации.
Версия исходников: **0.10.4**. [История версий](CHANGELOG.md) ведётся по
[правилам проекта](AGENTS.md).

**[Основная инструкция: автономная редакция на VM](docs/VM_EDITORIAL.md)** —
управление через Postiz, серверный цикл, PostgreSQL и правила восстановления.
[Паспорт компонентов](docs/COMPONENTS_AND_CONNECTIONS.md) дополняет её сведениями
о серверах, моделях и зависимостях. Датированные отчёты сохраняются как история;
прежние команды Hub не являются способом запуска действующей установки.

## Действующая установка

Основной проект работает в Linux VM 112 на Proxmox:
`editorial@10.20.30.45`, `/opt/max-postiz`.
[Postiz](http://10.20.30.45:4007/) и его раздел
[«Редакция»](http://10.20.30.45:4007/editorial) — единая панель из LAN/VPN.
[Автономная редакция](docs/VM_EDITORIAL.md) описывает серверный цикл,
миграцию журнала в PostgreSQL, общую паузу и ограничения источников.
Старый `max-postiz-hub.service` отключён, пользовательский порт 8090 снят;
история и связи сохранены. Единственный обработчик —
`max-postiz-editorial.service` (`editorial-agent`).
[Эксплуатация и перенос](docs/LINUX_DEPLOYMENT.md),
[автозапуск и проверка](docs/STARTUP_AND_HEALTH.md).
Данные входа хранятся отдельно от исходников в игнорируемых файлах.

Агент вызывает OpenCode **2.0.17** на `127.0.0.1:4108` внутри VM.
Общий LLM API — **http://10.20.30.95:8083/v1**. Переводчик новых автоматических
черновиков — исправленный **MADLAD `madlad400-3b-q4k-causal-v2`** с проверкой
contract и SHA worker/весов/tokenizer/config. Исторический Hy сохраняется;
независимая машинная проверка — `proxmox/qwen25-coder-7b`
(совместимое имя backend Ministral 3 8B). LanguageTool проверяет русский текст.
По новому решению владельца почасовой `max_test` работает **автоматически**:
MADLAD → независимый Ministral по рубрике `meaning-first-v1` → LanguageTool →
согласование точной версии политикой → MAX. Стилистические замечания не блокируют
отправку; существенные ошибки и hard gates блокируют. До двух адресных правок
Qwen каждый раз требуют новых Ministral/LT. Исходные отказы сохраняются,
человеческое согласование не имитируется. Qwen `proxmox/qwen35-9b` доступен другим
функциям; каскад Argos остаётся отдельным экспериментом.
Для новых автоматических записей предусмотрена [точечная проверка научных
написаний](docs/SCIENTIFIC_SPELLING.md) Хаббла, Годдарда и форм прилагательного
«звездообразующий» по первичным источникам. Raw LanguageTool сохраняется;
это не снимает смысловые ошибки, опечатки и прочие блокирующие замечания.
Postiz использует custom image `max-postiz-linux:0.10.0-editorial` на исторической
upstream-базе 2.25.1; версия этого image не является версией Python-проекта.

Postiz отвечает за редактор и календарь. Наш provider **MAX — браузер**
передаёт версии агенту. В почасовом режиме политика назначает дату того же
черновика и согласует точную версию/адресата/дату; после этого существующий worker
в `max-postiz-editorial.service` выполняет доставку через прежний Chrome transport.
Подбор, перевод и проверки также выполняются на VM, без desktop heartbeat.
Бот MAX для этого маршрута не нужен.
Вход владельца может потребоваться при истечении браузерной сессии.
[Действующая инструкция](docs/VM_EDITORIAL.md),
[инструкция адаптера](docs/MAX_BROWSER_ADAPTER.md).

## Текущий сценарий и площадки

- Почасовой цикл: полный разрешённый текст NASA SVS, NOIRLab IOTW или ESA/Hubble
  POTW, MADLAD → независимый Ministral → LanguageTool → Postiz → **автоматическая политика** → MAX. Только
  `max_test`, не чаще одного сообщения за 3600 секунд, без догоняющих пачек.
  [Штатная процедура](docs/VM_EDITORIAL.md),
  [история почасовых тестов](docs/HOURLY_ARTICLE_TESTS.md).
- В исходниках 0.10.0 реализован [резерв проверенных статей](docs/HOURLY_RESERVE_PLAN.md):
  запас 6, пополнение при 3, максимум 12; подготовка отделена от отправки. Включение
  требует общей паузы, миграции 0008 и сверки; по умолчанию режим выключен.
  Установка 0.10.0 подтверждена 26 октября: миграция, 417 VM-тестов, сохранённая
  история и 29 stack-checks. Новая живая доставка подтверждается отдельно в
  CHANGELOG; предыдущая подтверждённая доставка MADLAD — 25 октября на 0.9.5.
- MAX: тестовый канал `-79860712657053`, публичный адрес
  https://max.ru/channel_neurovideo_max. Между завершёнными публикациями
  адресат возвращается на паузу. Две статьи от 17 октября проверены 18 октября:
  точные тексты в MAX по одному разу, Postiz PUBLISHED и dispatch verified.
  Новый живой прогон 0.6.9 со статьёй NASA SVS 5643 завершён 18 октября в
  **06:22:32 МСК** (назначено 06:22:23): одна попытка, dispatch verified,
  Postiz PUBLISHED, точный текст в MAX один раз. В том историческом отчёте
  после сверки все адресаты были на паузе, активных dispatch и mutation leases
  не было. Эти результаты не подтверждают новую доставку после перехода на 0.7.0.
- Пикабу `pikabu_neuro_images`: ручной экспорт и подтверждение ссылкой;
  автоматическая публикация не заявляется. `pikabu_main` без привязки выключен.
- Telegram и VK выключены. Почасовая серия не включает остальные маршруты.
- Reddit API ожидает одобрения доступа. Режим 10 постов каждые 4 часа остаётся
  спецификацией и выключен: [план](docs/SERVER_REDDIT_AUTOMATION_PLAN.md).
  Есть ручная очередь и код IFTTT/Gmail intake, но живое подключение IFTTT
  не подтверждено: [документ приёма](docs/REDDIT_INTAKE.md).
- Vezdepost не установлен в действующей цепочке.

Почасовой выбор и контроль выполняет сервис VM. Desktop heartbeat не используется
и не должен запускаться параллельно. Запуск и общая пауза доступны в Postiz,
настройки источников изменяются на паузе. Согласование другим маршрутам этот
сценарий не даёт. Ранее созданные human-черновики не получают согласование задним числом:
для них нужна адресная аудируемая проверка новой рубрики. `sending/unknown` и mutation lease требуют сверки, повторять
неизвестную отправку нельзя. Наличие доступа к каналу не доказывает доставку.

## Проверка и резервный стенд

Основная проверка на VM без inference:

```sh
cd /opt/max-postiz
.venv/bin/python deployment/linux/check-stack.py
.venv/bin/editorial-agent status
```

С рабочего компьютера из корня проекта:

```powershell
.\scripts\check-startup.ps1
```

Проверка требует автономный режим нового сервиса и отключённый Hub. Второй worker
для проверки не нужен. `--deep` на VM или `-Deep` в PowerShell дополнительно
вызывает модели; это отдельная проверка inference, а не доставки в канал.
HTTP 200 и зелёный health не заменяют verified dispatch, Postiz PUBLISHED и
проверку точного сообщения в MAX.

Проверки предыдущей 0.6.9: **237 targeted tests на Windows**, **221 на Linux**.

узкой калибровки описаны в [истории версий](CHANGELOG.md). Ложное замечание
не разрешает публиковать отклонённый текст или повторять его ради согласия.
[Разбор сетевого сбоя](docs/NETWORK_RECOVERY.md),
[мера TSO и откат](docs/E1000E_RECOVERY.md).

Windows-скрипты `scripts/start.ps1`, `scripts/local_postgres.py`,
`scripts/serve_opencode.py` и `scripts/postiz.ps1` сохранены для локального
стенда и отката. Рабочий Linux-экземпляр и старый Windows worker нельзя
включать одновременно. Docker Desktop Windows не нужен Docker Engine VM.

Старые сетевые проверки, ожидающие Hub на 8090, не применяются как критерий
готовности Postiz-only. Исторический стенд не запускают против действующего
журнала PostgreSQL и одновременно с `max-postiz-editorial.service`.
