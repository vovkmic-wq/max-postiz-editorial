## Проверка изменений одной командой

Для разработки нужен **Python 3.12**, Git, Node.js и Google Chrome
(браузерные тесты открывают только изолированные HTML-фикстуры).
Из корня нового checkout в PowerShell:

```powershell
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock -r requirements-dev.lock -r requirements-browser.lock -r requirements-deployment.lock
.venv/Scripts/python.exe -m pip install --no-deps --no-build-isolation -e .
python scripts/check.py
```

На Linux создайте `.venv` командой `python3.12 -m venv .venv` и используйте
`.venv/bin/python` для установки теми же двумя командами pip. Если Chrome
отсутствует, установите его через Playwright: `.venv/bin/python -m playwright
install --with-deps chrome` (Windows: `.venv/Scripts/python.exe -m playwright
install chrome`). Node/npm OpenCode, веса моделей и `hub-agent init` для проверки
не нужны. Существующая `scripts/test.ps1` запускает ту же общую проверку.

Команда показывает результат каждого обязательного этапа и возвращает ненулевой
код при сбое. Отчёт JSON, JUnit и логи создаются в отдельном игнорируемом
`data/check-runs/<run>/`. Проверяются locks/окружение, зависимости, весь Ruff lint,
явная область форматирования, JavaScript, Chrome, полный pytest и whitespace diff.
После изменения версии переустановите editable-пакет второй командой pip.

Отдельный тест на Windows:

```powershell
New-Item -ItemType Directory -Force .test-state | Out-Null
.venv/Scripts/python.exe -X utf8 -B -m pytest tests/test_check.py -q --basetemp=.test-state/targeted
```

Базовый прогон не требует PostgreSQL; его пропуски явно отражены в отчёте.
Для проверки БД задайте **только отдельную тестовую** `TEST_DATABASE_URL` в текущем
окружении и выполните `python scripts/check.py --postgres`. Поддерживаются имена
БД `test_*` / `*_tests` без query-параметров; значение URL команда не выводит.
Postiz, MAX, OpenCode/MADLAD и LanguageTool относятся к отдельным живым проверкам:
успех pytest не подтверждает доставку в канал. CI в текущем репозитории отсутствует.
Критерии готовности, ограничения и порядок исправления — в
[руководстве проверки кода](docs/CODE_CHECKS.md).

## Как устроена публикация

1. Сборщик сохраняет полный оригинал, страницу, условия использования и credit.
   Для нового `article-illustrated-v2` берётся качественное изображение той же
   статьи из NOIRLab Image of the Week или ESA/Hubble Picture of the Week.
   Проверяются CC BY 4.0, частные исключения, точный URL, SHA и размер изображения.
2. Исправленный MADLAD `madlad400-3b-q4k-causal-v2` переводит текст. Независимый
   Ministral сверяет его с английским оригиналом, LanguageTool проверяет русский.
   При содержательном отказе отдельный Qwen может предложить не более двух
   адресных правок; каждый изменённый кандидат проходит новые Ministral и LT.
3. Проверенный материал попадает в PostgreSQL-резерв: цель 6, пополнение при 3,
   максимум 12, до трёх разных источников за проход. Долгая подготовка работает
   отдельно от короткого прохода отправителя.
4. При назначении слота создаётся один Postiz DRAFT, затем согласуется точная
   версия текста, изображения, адресата и даты. Политика автоматического `max_test`
   заменяет ручное согласование только в явно разрешённом почасовом сценарии.
5. Браузер MAX прикрепляет изображение перед текстом и в новом формате выделяет
   только заголовок жирным. Подпись сохраняет источник, лицензию и полный credit,
   использует «Перевод и адаптация.»; архивная и машинная строки исключены.

Интервал фактических доставок — не меньше 3600 секунд. Догоняющих пачек нет.
История всех источников, включая отменённые материалы, участвует в дедупликации.
Неизвестный результат модели, отправки или загрузки не разрешает повтор запроса.
`pending`, доступ к каналу и HTTP 200 не заменяют verified dispatch, Postiz
PUBLISHED и проверку точного сообщения с изображением в MAX.

Для будущих записей действует `hourly-practical-v2`: неровный стиль и
необязательная пунктуация сохраняются как advice, известные грамматические
замечания расходуют ограниченный языковой бюджет. Существенное искажение смысла,
основного объекта, числа, отрицания или причинности, невалидные ответы,
ошибки прав и инфраструктуры блокируют публикацию. Машинное согласие не является
гарантией отсутствия смысловой ошибки. Старые тексты и отказы воспроизводятся
по сохранённым рубрикам и промптам, без пересэмплирования или восстановления.

Отдельный `article-model-feedback-v1` передаёт Qwen полный EN, текущий RU,
числа, literal URL и каждое замечание без повторённых транспортных оболочек.
Полные raw остаются в snapshot/trace. Короткий версионированный промпт и
консервативный бюджет проверяются до editor claim и запроса; превышение
сохраняет известный отказ и источник. Неизвестный или failed claim блокирует
повтор прежде этой проверки. Каждый изменённый текст проходит свежие Min/LT.

## Источники и ограничения

Новый иллюстрированный формат разрешён только для проверенных оригинальных
изображений из указанных разделов NOIRLab/ESA/Hubble. Предпочтителен официальный
JPEG 2048×1536; минимально допустимо 1600 по длинной и 800 по короткой стороне.
Загрузка по ограниченным HTTP Range сохраняет ETag и доказательство каждого
диапазона (до 1280, общий предел 10 MiB); ошибки 401/403/429 не обходятся
повтором или сменой URL. Если права
или изображение не подтверждены, новый формат не отправляется одним текстом.
NASA SVS и прежние текстовые публикации сохраняются в истории; универсальное
разрешение на NASA-изображения не предполагается.

Разрешённый владельцем горизонт исходников — 43800 часов. Ограничение полного
оригинала остаётся 350 слов; действуют проверки прав и всей истории использования.
Корпус конечен: `no_source` означает отсутствие подходящего
неиспользованного материала, а целевой резерв не доказывает бесконечную
почасовую готовность. Для расширения корпуса нужны проверенные источники и
отдельное изменение политики. Подробности — [инструкция VM](docs/VM_EDITORIAL.md)
и [контракт резерва](docs/HOURLY_RESERVE_PLAN.md).

Reddit остаётся выключенной спецификацией до одобрения доступа и прав;
[план](docs/SERVER_REDDIT_AUTOMATION_PLAN.md). Пикабу поддерживает ручной экспорт,
Telegram и VK не включаются почасовой политикой. Vezdepost в рабочей цепочке нет.

## Запуск и эксплуатация

Рабочая директория Linux — `/opt/max-postiz`. Единственный systemd-сервис
`max-postiz-editorial.service` запускает `editorial-agent`. Postiz `/editorial`
доступен владельцу через закрытый LAN/VPN origin на порту 4007; API агента 8092
служит внутреннему BFF и провайдеру, отдельной пользовательской панели у него нет.
Старый Hub, Windows worker и desktop heartbeat параллельно не запускаются.

OpenCode используется на `127.0.0.1:4108`, общий API моделей —
`http://10.20.30.95:8083/v1`. Основной Qwen — `proxmox/qwen35-9b`, совместимый alias
Ministral — `proxmox/qwen25-coder-7b`. Контракт и SHA MADLAD worker, весов,
tokenizer и config проверяются отдельно. Argos остаётся экспериментом.

Схема PostgreSQL — 0008. Последний подтверждённый образ Postiz —
`max-postiz-linux:0.11.2-illustrated-cas`, на основе закреплённого
`0.10.8-reliability`. Python на VM — 0.11.7, import/metadata/health согласованы;
один перезапуск занял 4,751 секунды. Изолированная Linux/PostgreSQL qa-v25:
745 passed в 23 модулях, без ошибок и пропусков. Ранее полученные qa-v19/20/21/24, исходные
отказы тестовых постановок и датированные состояния сохранены в истории.
Тесты и установка сами по себе не подтверждают новую доставку в MAX.

Диагностика на подготовленной VM без публикации и inference:

```sh
cd /opt/max-postiz
systemctl status max-postiz-editorial.service --no-pager
curl --fail --silent http://127.0.0.1:8092/health
.venv/bin/python deployment/linux/check-stack.py
```

Общая пауза и настройки управляются из Postiz. Пауза агента не останавливает уже
назначенную очередь Postiz: перед обслуживанием сверяют QUEUE, `sending/unknown`,
claims и leases. API оставляют онлайн во время долгих тестов, сборки и backup;
короткий перезапуск выполняют с запасом до due и последующей проверкой здоровья.
[Основная процедура и датированные доказательства](docs/VM_EDITORIAL.md).

Git содержит исходники, тесты, промпты, правила проекта, документацию и безопасные
примеры конфигурации. Действующие `.env`, credentials, cookies, БД, изображения
постов, веса моделей, Docker volumes и приватные отчёты остаются в игнорируемых
файлах. Для переноса нужны отдельные закрытые backup обеих БД/runtime и нужный
custom image Postiz. Один `git clone` не восстанавливает авторизованный браузер.
Исторические [компоненты](docs/COMPONENTS_AND_CONNECTIONS.md),
[Linux-развёртывание](docs/LINUX_DEPLOYMENT.md) и
[проверки запуска](docs/STARTUP_AND_HEALTH.md) читают с учётом их дат;
при расхождении текущая инструкция — `docs/VM_EDITORIAL.md`.
