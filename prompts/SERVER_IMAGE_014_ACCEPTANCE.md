# Приёмка серверного образа 0.14.0 и мониторинга 0.13.3

Поручение владельца от 2 ноября 2026: довести серверный образ для существующих
MAX, Telegram и VK до успешной приёмки, включить в проверяемую копию мониторинг
из 0.13.3, исправить подтверждённые ошибки и проверить восстановление.
Работающий MAX на VM пока не трогать.

Работать в отдельном checkout и на новых изолированных экземплярах БД.
Не останавливать, не обновлять и не мигрировать рабочий сервер, его профили,
очереди, политики и расписание. Пикабу и Reddit этим поручением не включаются.
Тестовые секреты, backups, исходные ответы и отчёты хранить только в игнорируемых
приватных файлах; не передавать существующие приватные backups в GitHub Actions.

Сначала сверить уже выполненные native runs и сохранённые artifacts. Успех CI
не заменяет `accepted=true`, `native_checks_passed=true`, privacy/cleanup,
точные source/tree/manifest, image ID и SHA/размер переносимого Docker archive.
Прежний принятый artifact относится только к своим точным исходникам.

Проверять все PR checks, включая отдельный code-scanning check `CodeQL` и его
annotations. Успешный Actions workflow с jobs `Analyze` сам по себе не подтверждает
прохождение security gate. Новый HIGH alert воспроизводить и исправлять без
suppress/dismiss ради зелёного статуса. Credentials native-копии передавать через
ограниченный environment context, без лишней записи секретов в `.env.local`.

Монитор должен иметь собственные marker, PostgreSQL, SQLite и профиль.
Обычный запуск не выполняет миграцию или активацию. Проверить owner-only API,
свежесть heartbeat, watchdog, restart, SQL/SQLite restore и сохранность
unknown/queued без replay. В native-сценарии отправитель и команды выключены,
browser/Send запрещены; этот сценарий не является живой доставкой MAX/Android.

Для дефекта соблюдать порядок AGENTS: воспроизведение, содержательная регрессия,
минимальная правка, целевые проверки, единая команда и `--postgres` с отдельными
тестовыми БД, независимое ревью, согласованные версии и новая запись CHANGELOG.
Затем выполнить полную native-приёмку окончательного commit и сохранить artifact.

Существующий локальный backup восстанавливать только в новую пустую копию.
Сверить все сохранённые строки, историю, approvals, attempts, claims, slots,
pending и unknown до и после round-trip и явной миграции. Если схема не меняется,
назвать upgrade проверенным no-op. Исторический editorial-only frame не выдавать
за свежий согласованный backup действующих Postiz и редакции.

Готовность образа, восстановление копии, живой вход в аккаунты и перенос на VM
подтверждаются разными доказательствами. Развёртывание на рабочую VM этим
поручением не разрешено.
