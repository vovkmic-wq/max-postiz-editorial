# Промпт установки Docker и развёртывания Postiz

Продолжение от 13 октября 2026: для MAX без бота применяй
`prompts/MAX_BROWSER_ADAPTER_PROMPT.md` и overlay max-browser.
Не переключайся на Vezdepost Bot API provider из-за отсутствия токена.

Работай в `C:/script/20261011-Max postiz`. Установи Docker на этой Windows-машине
из официального источника и разверни Postiz по canonical Compose из
`gitroomhq/postiz-docker-compose`, закрепив commit и образ Postiz по tag/digest.
Сначала проверь существующие процессы, WSL, порты и конфигурацию. Не меняй
прежние проекты MAX и Пикабу, их БД или браузерные профили.

Сохрани действующую связку редакции: PostgreSQL → OpenCode на
`127.0.0.1:4108` → `http://10.20.30.95:8083/v1`, основная модель `proxmox/qwen35-9b`,
второй выбор `proxmox/qwen25-coder-7b` (Ministral 3 8B).
Postiz размести на loopback `http://localhost:4007`; его PostgreSQL, Redis,
Temporal и постоянные volumes должны быть отдельными от БД редакции.
Секреты создай локально и сохрани только в игнорируемом `.env`.

Проверь Compose, Docker Engine, состояния контейнеров, HTTP-редактор,
миграции и сохранение данных после перезапуска. Подключи Postiz Public API
к редакции после создания локального владельца и API-ключа. Не публикуй
внешние сообщения при проверке; проверку редактора проводи черновиком.
MAX и Пикабу сохраняют прежние маршруты, Telegram и VK остаются отключёнными.
Согласование внутри Postiz не объявляй обязательным, пока ACL/guard
не подтверждён; `approval_guard_verified` автоматически не включай.

Если WSL/виртуализация требуют прав или перезагрузки, выполни всю доступную
подготовку, запиши точную причину и оставшееся действие. Не перезагружай
машину с открытыми проектами без отдельного указания владельца.

Веди `CHANGELOG.md` постоянно по правилам `AGENTS.md`: при каждом изменении
записывай дату, версию, проверенные результаты и ограничения. Обнови README,
развёртывание и отчёт приёмки по фактическим результатам. Не записывай секреты
в историю, логи, документы или исходный ZIP.
